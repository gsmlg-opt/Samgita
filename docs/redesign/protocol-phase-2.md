# Phase 2: independent protocol packages

The user authorized this phase after `1574130`. Its bounded B0 reconciliation is: the current umbrella has two platform apps and no reusable protocol; the protocol needs none of the removed schemas, migrations or readers. Build standalone Mix projects under `apps/`, matching repository layout, but omit umbrella build/dependency/config inheritance and leave the root application's explicit app list unchanged. Historical migration reconciliation remains open for platform work. No P1/P3 implementation, database, external repository, production endpoint or deployment is in scope.

## Implementation units and gates

1. `apps/samgita_protocol`: dependency-free Elixir 1.18+ library. Pure schemas, codec, capabilities, client/connection state, server handler interface and bounded replay log. Test malformed messages before dispatch, correlation, negotiation, duplicate responses, uncertainty, timeouts, replay gaps and limits.
2. `apps/samgita_protocol_websocket`: optional standalone RFC 6455 JSON-text transport and explicitly started fake Agent at `/app-server`. It depends on the core and declared WebSocket/HTTP libraries, never Phoenix or platform configuration. Test real loopback upgrades, authentication, bidirectional requests/approvals, events, errors and reconnect without automatic command replay.
3. `apps/samgita_protocol_codex`: optional standalone adapter with official pinned schemas, hashes and license provenance. Test only the documented subset against those fixtures; real-client compatibility remains unverified unless independently demonstrated.
4. Core standalone consumer under `examples/consumer` builds with only its path dependency. Compile/test all three packages and that consumer from their own directories, check formatting/diff/scope, record evidence, commit and stop. Serialize Mix builds; module/schema ownership is disjoint between workers.

## Native v1 contract

Envelope fields: `schema_version: "1.0"`, `type: "request" | "response" | "notification"`, required nonempty `correlation_id`; optional `causation_id`, opaque `project_ref` and `task_ref`. Task references require a Project reference. Requests/responses have a nonempty string `id` scoped to a connection; requests/notifications have `method` and object `params`. A response has exactly one object `result` or typed `error`. A state-changing request additionally requires a stable `command_id`; request IDs are not durable idempotency keys. Responses echo the original correlation/context/command metadata. Unknown fields, versions, methods and malformed payloads fail before handler dispatch. Neither refs nor session IDs confer authorization.

`connection/initialize` accepts `versions`, `capabilities`, optional `required_capabilities` arrays. Its result contains selected `version`, `capabilities`, `connection_id`. A successful response completes native initialization; Codex's separate `initialized` notification belongs only to its adapter. Negotiation intersects advertised groups, rejects missing required groups, and never invents fallback support. Handler `methods/0` must equal all request methods of its advertised groups (excluding built-in initialization).

| Capability | Request methods and parameters | Result |
| --- | --- | --- |
| `project_events.v1` | `project/event.receive` (`event`); `project/event.status` (`event_id`); `project/event.report` (`event_id`, `decision_id`, `status`: completed/failed/rejected, `decision` object, optional JSON `result`) | Receive: `event_id`, `delivery_attempt_id`, `acceptance`: received/durable, `processing_status`: pending/processing/completed/failed/rejected. Status: same event/acceptance/processing fields, optional decision/result. Report: `event_id`, `decision_id`, `report_status`: recorded, `management_acceptance`: not_requested/accepted/rejected. |
| `sessions.v1` | `thread/start` (optional `title`, `metadata`); `thread/read`, `thread/resume` (`thread_id`); `turn/start` (`thread_id`, `input`); `turn/steer` (`thread_id`, `turn_id`, `input`); `turn/interrupt` (`thread_id`, `turn_id`) | Thread calls: `thread_id`, optional JSON `thread`. Turn start/steer: `thread_id`, `turn_id`, `status`: running. Interrupt: `thread_id`, `turn_id`, `status`: requested/interrupted/already_finished. Input is a nonempty array of `{type: "text", text: string}`. |
| `streaming.v1` | `stream/resume` (`stream_id`, nonnegative integer `cursor`) | `stream_id`, `cursor`, `events` array of valid stream notifications; a gap is an explicit error. |
| `approvals.v1` | Bidirectional `approval/request` (`approval_id`, `thread_id`, `turn_id`, `action` object; optional `expires_at`) | `approval_id`, `decision`: approve/deny, `scope`: once. Approval responses are bound to the exact pending request; the protocol never approves automatically. |
| `cancellation.v1` | `request/cancel` (`request_id`) | `request_id`, `status`: requested/already_finished. Cancellation requests intent, not proof that an effect stopped. Use turn interruption for a running turn. |

All requests except initialization, event status, thread read and stream resume are state-changing. Project-event receive/report and runtime execution are separate operations; an event is not a turn or an instruction to run tools.

An event has `schema_version`, stable `event_id`, unique-per-attempt `delivery_attempt_id`, immutable UTC `created_at`, `correlation_id`, optional `causation_id`/refs, nonempty `type` and object `payload`. `Event.retry/2` changes only delivery attempt identity. The host deduplicates event content by original event ID; retrying delivery does not create a second event. A WebSocket write/transport receipt is not durable acceptance. `acceptance: durable` may be emitted only by a host that committed its inbox. Processing completion and recording a decision are separate from an authoritative Project/Task transition; `management_acceptance` is reported only by that authority. The in-memory fake uses `received` and `not_requested`.

Notifications: `project/event.updated` (event_id/acceptance/processing_status), `thread/started` (thread_id), `turn/started` (thread_id/turn_id), `turn/completed` (thread_id/turn_id/status completed/failed/interrupted), and `item/started`, `item/delta`, `item/completed` (thread_id/turn_id/item_id and item object or delta string). Replayable notifications carry both opaque `stream_id` and positive integer `cursor`; notifications without both are ephemeral. Cursor order is per stream. Replay uses a bounded log, returns at most 128 events per page and fails with `replay_gap` outside retention. A resume result's cursor is the last returned cursor, or the requested cursor for an empty page. Foreign-stream/noncontiguous results fail. A client drains notifications and explicitly acknowledges its processed cursor; socket receipt alone does not advance that checkpoint. Hosts own checkpoint durability and authorization.

## Public interfaces and failure semantics

`Error` is a struct with string `code`, safe `message`, boolean `retryable`, object `details`; `Error.new(code, details \\ %{})`, `to_map/1`, `from_map/1`. Stable codes include parse_error, invalid_message, invalid_params, invalid_response, unsupported_version, unsupported_method, unsupported_capability, not_initialized, already_initialized, capability_mismatch, correlation_mismatch, unknown_response, conflicting_response, buffer_full, too_many_requests, disconnected, ambiguous_disconnect, timeout, cancelled, replay_gap, stale_cursor, stale_connection, conflict, not_found, handler_error, unauthorized and upstream_error. Error messages never interpolate input payloads or secrets.

`Codec.encode/2` and `decode/2` return `{:ok, value}` or `{:error, Error}`. Default frame limit is 1 MiB. There is no automatic listener or application supervisor.

- `Client.new(opts) -> {:ok, client}`; options include capabilities, max_pending (64), max_buffer (128), max_completed (128), max_streams (64), max_frame_bytes, request_timeout_ms (30_000), and externally persisted processed checkpoints.
- `Client.request(client, method, params, opts) -> {:ok, message, client} | {:error, error, client}`; opts carry id, command_id, correlation_id, context and optional now_ms/timeout_ms. No message is sent by the core.
- `Client.receive(client, map_or_json) -> {:ok, effects, client} | {:error, error, client}`. Effects are `{:response, id, result}`, `{:error, id, error}`, `{:notification, message}`, `{:request, request}`. Correlation/context is checked before resolving pending requests; duplicate responses never dispatch twice.
- `Client.receive_replay(client, correlated_result)` explicitly ingests a successful resume result through the same cursor/buffer checks atomically. The optional WebSocket client calls this and forwards notifications before returning the result. Plain core consumers call it themselves.
- `Client.reply(client, original_request, {:ok, result} | {:error, error})` returns the request tuple shape with a correlated response. The request must still be pending; approval responses cannot be reassigned to a different request.
- `Client.disconnect/1 -> {:ok, effects, client}`; sent mutations become `ambiguous_disconnect` and stay unresolved, read requests become disconnected. `Client.reconnect/1 -> {:ok, client}` requires fresh initialization and never resends work. `Client.expire(client, now_ms)` yields timeout effects; sent mutation timeouts are ambiguous too. The caller reconciles original command/event IDs with the host before any deliberate retry.
- `Client.drain(client, limit) -> {messages, client}`; `Client.ack_cursor(client, stream, cursor) -> {:ok, client} | {:error, error, client}`. `Client.checkpoints/1` exports processed cursors for `new(checkpoints: map)` restoration. Overflow returns buffer_full; close/backpressure before advancing unseen positions instead of silently dropping state events.
- `Server.new(handler, handler_state, opts) -> {:ok, server} | {:error, Error}`; `Server.receive/2 -> {:ok, response_messages, server} | {:error, error, server}`. `Server.request/4` has the client request tuple shape and correlates server-initiated requests. Handler callbacks: `capabilities/0`, `methods/0`, `handle_request(method, params, context, state) -> {:ok, result, state} | {:error, Error, state}`; optional `handle_notification/4` and `handle_response(method, {:ok, result} | {:error, Error}, context, state) -> {:ok, state}`. A server-initiated request requires the response callback. Context includes all request identity/ref fields and connection_id. Hosts authenticate before dispatch and own persistence/idempotency; a protocol response cache cannot provide durable exactly-once effects.

WebSocket adapter configuration is explicit and local to each instance. Authenticate before upgrade; do not place bearer tokens in URLs/logs. Use WSS outside loopback, no redirect following, no implicit target selection. Reconnect authenticates again; old transport messages cannot settle a new connection's request. Shared server state and replay retention belong to the host, never the core's global configuration. Detailed runnable usage and test evidence live in package READMEs and the phase record below.
